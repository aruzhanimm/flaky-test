Дополнительный исследовательский анализ после рецензии
Дата: 15 октября 2026. Основные результаты main_v3 уже известны.
Это заранее зафиксированный план последующего exploratory-анализа, не независимая подтверждающая проверка и не preregistration.

RQ, aim, objectives, корпус 1051 теста, метки и группировка main_v3 сохраняются. Исходные результаты не заменяются. Основной эффект v3 остаётся исходным ответом на RQ. Все последующие сравнения публикуются, без выбора наиболее выгодного результата и без новых p-values.

1. Аудит
Проверить исходные артефакты, повторный разбор логов, метрики собственным вычислением, разбиения, точное совпадение original/full с сохранёнными predictions, словарями и коэффициентами main_v3. Проверить соответствие каждой изменившейся строки исходному corpus. Не запускать Java/Docker и не заявлять такую репликацию.

2. Разложение маскирования
Выполнить полный набор 2^3 комбинаций переключателей T (test class/method replacements), R (repository URL/name/component replacements), P (whole path replacements). Все восемь комбинаций используют один корпус, одинаковые folds и прежний LR/TF-IDF config. Порядок операций и защита exception names те же, что в representations.py v2. Нулевая комбинация обязана совпасть с original, TRP — с masked посимвольно для каждого теста. Эти переключатели обозначают операции, не взаимно исключающие семантические виды: например, R может менять имя внутри пути даже без P. Сохранить фактическое число изменённых текстов, результаты всех комбинаций и взаимодействия; не интерпретировать операции как чистое причинное разделение источников информации.

3. Все изменившиеся предсказания
Для всех 56 изменений и всех 10 затронутых групп сохранить категорию, источник/формат, объём проекта, длину текста/словаря, логи, исходный provenance, влияние отдельных комбинаций и два диагностических контрфактических предсказания: original-модель(masked-текст), masked-модель(original-текст). Оба предсказания получаются на исключённом проекте. Это проверка чувствительности fixed fitted model, а не дополнительная оценка рабочего сценария.
Разложить изменение score contrast новой против старой категории по пути original model/original text -> original model/masked text -> masked model/masked text. Остаточная часть объединяет изменения словаря, IDF, нормализации и коэффициентов. Это алгебраическое разложение score, не объяснение реальной причины flaky-сбоя. Сохранить наибольшие вклады токенов для каждого случая. Проверить всю группу, не выбирать красивый пример.

4. Confounding
Показать полные category x format и category x project таблицы и пустые ячейки. Стратификация по формату не может идентифицировать четыре категории, если общего покрытия нет.
Если имеются минимум две категории с >=3 группами каждая в одной семье сборщика, провести отдельное original/full сравнение внутри такой семьи с обучением и оценкой только на ней. Предпочтение: Surefire OD/TD; объединение XML/TXT в одну семью явно раскрывается, точные форматы также табулируются. Эта проверка относится только к этой подзадаче и не устраняет selection bias или редкость TD.

5. Дополнительная модель
LinearSVC на том же word TF-IDF, C=1, class_weight=balanced, dual=auto, loss=squared_hinge, max_iter=10000, tol=0.0001, random_state=20261013, остальные параметры sklearn defaults. Оценить original/full на всех исходных project folds. Настройку параметров по результатам не выполнять. Любая ошибка сходимости останавливает проверку и раскрывается. Это другая линейная целевая функция, а не доказательство для нейросетей или любых представлений.

6. Внешняя выборка
Проверить документацию публичных кандидатов: iDoFT, FlakyCat, FlakyLens и доступные артефакты новых работ. Для пригодной независимой проверки нужны Java target-failure logs, совместимые категории, revision/project IDs и исключение пересечений с ReproFlake. Метаданные/исходный код теста или дополнительные записи того же источника не объявлять независимым корпусом. Если сопоставимой готовой выборки не подтверждено, сохранить причины для каждого проверенного кандидата, не утверждая, что подходящих данных нигде не существует.
